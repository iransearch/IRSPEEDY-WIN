# تغییر رمز سرویس از اپ ویندوز

مسیر: `https://shop.ir-speedy.online/app-change-password.php`

فقط درخواست `POST` با نوع `application/x-www-form-urlencoded` پذیرفته می‌شود. ساختار فرم با درخواست قبلی `ChangePassword` سازگار است؛ `email` در این مسیر نادیده گرفته می‌شود و `wkey` لازم نیست.

| فیلد | مقدار |
| --- | --- |
| `Action` | `ChangePassword` |
| `email` | اختیاری؛ اگر اپ قبلاً می‌فرستد، سرور آن را نادیده می‌گیرد |
| `username` | نام کاربری فعلی سرویس |
| `password` | رمز فعلی سرویس |
| `newuser` | نام کاربری جدید؛ برای تغییر فقط رمز، برابر `username` |
| `newpass` | رمز جدید |

هدر اضافه: `X-IRSPEEDY-Client: windows-v1`

نمونه درخواست:

```http
POST /app-change-password.php HTTP/1.1
Host: shop.ir-speedy.online
Content-Type: application/x-www-form-urlencoded
X-IRSPEEDY-Client: windows-v1

Action=ChangePassword&username=example1&password=old123&newuser=example1&newpass=new123
```

موفق: `HTTP 200` و `{"st":true,"code":0,"msg":"درخواست تغییر رمز ثبت شد"}`. هدر نامعتبر یا نبودن آن: `HTTP 403` با `code: 34`. نام کاربری یا رمز فعلی نامعتبر: `HTTP 403` با `code: 32`. اگر همین نام کاربری و رمز به چند سرویس تعلق داشته باشد: `HTTP 409` با `code: 36` و هیچ سرویسی تغییر نمی‌کند. سایر خطاها در `msg` توضیح داده می‌شوند. پس از دریافت پاسخ موفق، تغییر در صف سرویس ثبت می‌شود؛ پاسخ به معنی اتمام قطعی اعمال تغییر در سرور سرویس نیست.

اپ باید این درخواست را فقط از طریق HTTPS ارسال کند. رمزها را در URL، لاگ اپ یا گزارش خطا ننویسید. مسیر قبلی `rpwservice.php?Action=ChangePassword` همچنان به `wkey` نیاز دارد و تغییری نکرده است.

**محدودیت امنیتی:** مقدار این هدر عمومی و قابل کپی است؛ اثبات نمی‌کند درخواست واقعاً از اپ ویندوز آمده. این مسیر علاوه بر هدر، نام کاربری و رمز فعلی همان سرویس را بررسی می‌کند؛ ایمیل به‌عنوان مجوز سراسری استفاده نمی‌شود. کلید وب‌سرویس در فایل API قرار داده نشده، چون این مسیر اصلاً از احراز هویت نماینده با `wkey` استفاده نمی‌کند. اگر در آینده احراز هویت قوی اپ لازم شد، باید کلید اختصاصی دستگاه یا امضای درخواست اضافه شود.

## رفتار کلاینت ویندوز

- فیلد سازگاری `email=info@irspeedy.us` ارسال می‌شود؛ سرور آن را نادیده می‌گیرد.
- فقط ترکیب HTTP 200، `st=true` و `code=0` مسیر ورود فوری با رمز جدید را فعال می‌کند. پاسخ صف به‌تنهایی باعث ذخیره رمز جدید نمی‌شود؛ ذخیره پس از ورود موفق انجام می‌شود.
- خطای HTTP 409 / code 36 مانع ورود مجدد می‌شود و پیام سرور نمایش داده می‌شود. اگر پیام خالی باشد، پیام فارسی مشخص درباره تداخل چند سرویس نمایش داده می‌شود.
- در صورت ناموفق بودن ورود، رمز جدید برای تلاش مجدد در فیلد پوشیده ورود باقی می‌ماند. درخواست تغییر رمز خودکار تکرار نمی‌شود.
